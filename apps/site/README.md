# `@libriant/site` — the public website at libriant.com

A bilingual static site. Greek at the root, English under `/en`. No JavaScript,
no cookies, no analytics, and **no request to any external server** — which the
privacy notice says out loud, so keep it true.

Generated by `build.ts` into `dist/`, which is baked into the edge image and
served by Caddy on the Hetzner server. The application form posts to the API.

```
libriant.com        this site
app.libriant.com    the product
admin.libriant.com  the admin panel
```

## Build it

```bash
pnpm --filter @libriant/site build         # strict — refuses on a placeholder
pnpm --filter @libriant/site build:draft   # stamps a loud banner instead
```

`dist/` is gitignored on purpose: it is a production artefact, rendered in CI
and never committed.

## What generates what

| Source                         | Becomes                                              |
| ------------------------------ | ---------------------------------------------------- |
| `content/pages.{el,en}.json`   | the eight content pages, rendered by `src/render.ts` |
| `content/*.{el,en}.md`         | the privacy notice and offer terms                   |
| `src/pages.ts`                 | home, thank-you, 404, and the application form       |
| `src/copy.ts`                  | page chrome in both languages                        |
| `src/plans.ts`                 | the pricing cards and comparison table               |
| `locales/{el,en}/landing.json` | the hero, feature cards and closing CTA              |
| `assets/icons/*.svg`           | copied to `dist/icons/`                              |
| `public/*`                     | copied verbatim                                      |

Two things are deliberately **not** hand-written:

**The pricing table reads `packages/db-control/prisma/seed-data.ts`**, so the
caps the site advertises are the caps the software enforces. Six of the fifteen
feature keys are excluded, each for a correctness reason documented in
`src/plans.ts` — read that comment before adding a row.

**`site.config.json` is the only file with identity and offer values in it.**
The build refuses to emit while any value still reads `[LIKE THIS]`, because
those values print in the page footer and the privacy notice, where GDPR Art. 13
requires the controller to be identifiable.

## The copy gate

`build.ts` lints every emitted page and **fails the build** on a violation. It
is not a style checker — it exists because several false claims reached the
site before it did. When it fires, fix the copy; only relax a rule when the
underlying fact has changed.

It enforces, per language: tonos on Greek all-caps, brand gender («το Libriant»,
never «η»), πακέτο not πλάνο, δανεισμός not δάνειο, currency conventions
(«19 €» in Greek, «€19» in English, never «0 €»), typographic quotes, no
company or trademark language, no ISO dates in prose, and no untranslated Greek
left on an English page.

## Running it locally

The site is static, so anything that serves files works:

```bash
pnpm --filter @libriant/site build:draft
npx serve apps/site/dist          # or python3 -m http.server -d apps/site/dist
```

**The form will not work this way** — `POST /apply` is an API route, and locally
the site and the API are two different origins. To exercise the form end to end,
put a Caddy in front that serves `dist/` and proxies `/apply` and `/en/apply` to
the API on :3001; see `docs/RUNBOOK.md`.

## Changing the offer

`site.config.json` → `offer.spotsRemaining`. Decrement it when a library is
accepted and redeploy. At zero the form is replaced by a waiting-list notice and
the API refuses submissions.

A claim of "the first five" has to actually be true, so this is a discipline,
not a setting.

## These legal pages are not the product's legal suite

`content/privacy.{el,en}.md` and `content/programme-terms.{el,en}.md` cover this
website and this form only — purpose-written, short, and scoped to collecting an
application. The product's own legal documents live in `locales/*/legal/` and
are a separate, much longer set that still needs counsel review.

`legal.lastUpdated` in `site.config.json` is recorded with every consent, so
bump it **only** when the text actually changes, never on a rebuild.

## `public/sw.js` — do not delete

A service worker whose only job is to unregister itself. The product was once
served from this origin and its PWA registered a worker at scope `/` that caches
pages and API responses, including tenant data. Letting `/sw.js` 404 would leave
that worker in control of navigations here. The file explains itself; leave it
in place until no browser could still hold the old registration.

## Onboarding an accepted library

Nothing here is automatic — the site collects applications, a human decides.

1. Export the applications: `admin.libriant.com/lbr-api/admin/applications.csv`
   (admin session required).
2. Create the tenant: `pnpm tenant:create`.
3. Assign the **Municipal** plan with `billingMode = 'manual'` and `paidUntil`
   set twelve months out. `effective-plan.service.ts` expires manual plans on
   that date, so honouring the offer needs no code.
4. Decrement `offer.spotsRemaining` and redeploy.

## DNS

Separate from this package but easy to forget: `_dmarc.libriant.com` should
carry a DMARC record. The campaign sends from this domain, and monitoring-only
(`p=none`) is safe to add at any time.
