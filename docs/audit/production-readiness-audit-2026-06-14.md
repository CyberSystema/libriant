# Libriant — Final Production-Readiness Report

## 1. Executive Summary & Verdict

Libriant is a multi-tenant library SaaS (NestJS + Next.js monorepo) with a broad, well-structured feature set and notably clean foundations in several areas (SQL parameterization, tenant query isolation, secret hygiene, dependency provenance). However, the review surfaced **four confirmed criticals** and a dense band of **fourteen confirmed highs** that together touch billing correctness, irreversible data loss in ops tooling, authorization on the privileged admin plane, plan/quota enforcement, and core circulation/notification flows.

The most severe issues are not edge cases: every real paid Stripe signup silently desyncs (billing-1), the documented disaster-recovery cleanup command drops the _live_ database (infra-1 / ops-dr-1 / prov-1), an unauthenticated endpoint provisions a Postgres database per request with no rate limit (ratelimit-1 / auth-3), and a "support"-tier admin can destroy any tenant with no role check (adminplane-1).

### PRODUCTION-READINESS VERDICT: **Not ready**

> The combination of a billing-sync critical that breaks on every real subscription, a data-loss footgun wired into the documented DR runbook, unauthenticated DB-provisioning DoS, and missing admin-role enforcement means shipping today risks money/access corruption, irreversible per-tenant data loss, and platform destruction by a low-privilege insider. These must be fixed and verified first.

**Severity counts (confirmed/verified):** 4 critical · 14 high · ~18 medium · ~35 low · ~9 info.

## 3. Should-Fix (Confirmed/Verified Mediums), grouped by theme

**Billing**

- **billing-2** `billing.service.ts:217` — `startCheckout` doesn't enforce `plan.isPublic` (other paths do); an owner/admin who knows a hidden stripe-priced plan's slug can subscribe to it. _No out-of-box target._ Fix: add `|| (!plan.isPublic && plan.id !== sub.planId)`. _(Originally high; downgraded.)_
- **billing-3** `stripe-webhook.controller.ts:71-116` — a hard crash between Redis SETNX and dispatch can permanently drop one billing event (sweep won't rescue an `error=null` row). Fix: persist the DB row before the Redis lock; broaden the sweep to `processedAt IS NULL`.

**Reliability / observability (worker health)**

- **reliability-2 / reliability-obs-new / queue-4 / quota relate** `worker.ts:76,53` — worker `/readyz` and the Compose `/healthz` healthcheck never check live Redis or all sub-workers; a dead-but-alive worker keeps reporting healthy. _Note:_ single-host Compose won't auto-restart on `unhealthy`, so the **load-bearing fix is an alert** (queue backlog/stall) plus pinging each BullMQ connection in `/readyz` and including all 5 sub-workers.
- **reliability-1** `docker-compose.prod.yml:289` — BullMQ shares Redis with `allkeys-lru`; safe only because no `--maxmemory` is set. Fix: dedicated `noeviction` Redis for queues; set `maxmemory` + alert.
- **reliability-3** `export-processors.ts:192` — untimed `pg_dump` + no `stop_grace_period`; redeploy SIGKILLs in-flight exports, leaving rows stuck `running`. Fix: add timeout/killSignal, set `stop_grace_period`, reap `running` jobs at startup.
- **reliability-4** `stripe-real.driver.ts:31` — Stripe client has no timeout/retry budget (80s default); a Stripe latency event ties up request workers. Fix: `{ timeout: 10000, maxNetworkRetries: 2 }`.
- **reliability-7** `email-worker.ts:147` — dead-lettered emails have no metric/alert. Fix: expose delivered/failed/dead counters + alert.

**Concurrency in circulation / quota**

- **holds-race-1 / queue-2** `reservation-expiry.job.ts:125-146` — sweep flips a copy to `reserved` with an unguarded update (no `status='available'` CAS), can clobber an `on_loan` copy / double-allocate. Fix: `updateMany({ where:{ id, status:'available' }})` + count check.
- **circulation-new** `reservation-expiry.job.ts:108-113` — freeing a held copy with an unguarded update can clobber a manually lost/damaged copy back to `available`. Fix: add `status:'reserved'` guard.
- **members-1** `members.service.ts:411-429` — TOCTOU between active-loan/hold check and archive write; archived member can keep active circulation. Fix: single tx + member row lock or re-validate inside checkout tx.
- **catalog-members-new** `copies.service.ts:159-161` — archiving an `on_loan` copy bypasses the transition guard (durable inconsistent state on a single request). Fix: refuse `archivedAt` when `status==='on_loan'`.
- **jobs-new (fine amount)** `fine-accrual.job.ts:100-107` — non-transactional amount UPDATE can revert a return-flow finalisation (lost write of a capped/waived amount). Fix: guard `where:{ loan:{ status:'active' }}` or Serializable.
- **quota-3 + plans-quota-new** `storage.service.ts:64-101` + `registry.ts` — storage quota is a lock-free check-then-write with a best-effort counter, **and** the `recomputeUsage` reconciliation job that's supposed to heal drift is **never scheduled** (only a manual admin endpoint). Fix: serialize under a control-plane advisory lock, make the counter mutation atomic, and actually register the nightly recompute job.

**Scheduled-job / queue observability**

- **queue-5** `scheduled-jobs.runner.ts:82-100` — health snapshot records only successes; a continuously failing cron looks healthy. Fix: record failures into `lastResults` + failure metric.
